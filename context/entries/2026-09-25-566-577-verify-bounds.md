# 2026-09-25: verify-in-worktree says what every arm ran over (#566, #577)

Branch `track1/verify-bounds`, branch-start base `0dcc599`.

## Why

`scripts/verify-in-worktree.sh` prints a bound for every mode, so that a
green says what it covered. Three places fell short of that rule.

- **`--all` stopped at the first red.** Under `set -e`, a red tsc or vitest
  ended the script before the later arms printed a header, and nothing said
  they had not run. #450's dead lint arm stayed invisible partly this way (#566).
- **The eslint arm printed no bound (#566).**
- **The vitest arm had three gaps (#577).**
  - It accepted exit 0 with no `Test Files` summary.
  - It counted `*.spec.ts(x)` on disk, which vitest never includes.
  - The gate's stub printed a vitest summary typed from memory.

## What changed

- **`--all` runs every arm.** Each arm runs as a child process of the script,
  and the run ends with a summary like `--all -- tsc 2, vitest 1, eslint 1
  (all three ran; ...)`. It exits with the worst status, 2 outranking 1.

  The arms are child processes, not `tsc || st=$?`, because bash ignores
  `set -e` inside a function called from an `||` list.
- **The eslint bound is ESLint's own count.** The arm sets
  `DEBUG=eslint:eslint`, which is an environment variable and changes no flag
  or verdict. It reads ESLint's `N file(s) found` line and drops the debug
  lines from what it prints. No such line, or 0 files, is could-not-look.

  Measured 2026-09-25 with ESLint v9.39.5: 399 files. A `find` over the same
  tree, minus `node_modules` and `.next`, also gave 399.
- **vitest.**
  - Exit 0 now needs the `Test Files ... (N)` summary too.
  - The disk count uses vitest's include, `src/**/*.test.{ts,tsx}`.
  - The count is cross-checked against vitest's own total, and a disagreement
    is could-not-look. That turns the copied include pattern into a check
    that fails loudly on drift.
- **The gate's stub lines are captured, not typed.** They were captured on
  2026-09-25 from vitest 3.2.7, running one passing, one failing and one
  uncollected file:
  - `FAIL  <f> > <test>`;
  - `FAIL  <f> [ <f> ]`;
  - `Test Files  2 failed | 1 passed (3)`.

## Verified

- `tests/gates/verify_in_worktree_status.sh`: PASS. New cases:
  - vitest with no summary;
  - a vitest total disagreeing with the disk;
  - a clean vitest reading 2/2 with a `.spec.ts` on disk;
  - eslint with no count, and with a zero count;
  - debug lines not printed;
  - `--all` over tsc 2 / vitest 1 / eslint 1 (exit 2, all three summarised);
  - a clean `--all`;
  - `--all` naming eslint's could-not-look.
- Red-on-revert, driving the gate with Git Bash named explicitly. A bare
  `bash` from `python.exe` resolved to WSL and ran nothing, and the harness
  refused to count that as red. The baseline was exit 0, and 6 of 6 mutations
  went red:
  - the old sequential `--all`;
  - the vitest summary check removed;
  - the vitest total cross-check removed;
  - `.spec` counted again;
  - the eslint count requirement removed;
  - a zero eslint count accepted.
- A real `--all` against containers: tsc 0 errors, vitest 78/78 (its total
  agreeing with the disk), eslint 399 files; exit 0.
- `--self-test` PASS, `--self-test-bound` PASS,
  `tests/gates/verify_in_worktree_mounts.sh` PASS, and
  `tests/gates/argument_guards.sh` PASS.

## Limits

- The eslint bound depends on ESLint's debug text. A format change fails
  closed (could-not-look), not open.
- The vitest include is still copied, not read from `vitest.config.ts`. A
  drift is caught by the cross-check with vitest's own total, not prevented.
- A `passWithNoTests` run that prints a `Test Files` line with a zero total,
  if one exists, is compared against the disk and refused on a mismatch. It
  has not been measured.
