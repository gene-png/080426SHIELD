## Fixed here

- **#307: the `reasons` order was asserted by nothing.** A unit test pins
  `schema_reasons` against literal input: first-seen order kept, repeats
  dropped, a missing type named `schema_unknown`. The route test also ties the
  first reason to the first reported detail. That line cannot tell first-seen
  from sorted on its own, because the only payloads this route accepts produce
  types already in alphabetical order, and the test says so.
- **#307 (advisory): the same-type branch of the `reason` choice.** Two errors
  of one type give that type's code, not `schema_multiple`. Tested through the
  handler, because no route here produces two errors of one type in one
  request.
- **#307 (prose): `schemas/zt.py`** named `schema_extra_forbidden` as what a
  client reads. The `mode="before"` validator runs first, so the code is
  `schema_unapplied_fields`, which the tests assert.
- **#308: the proxy test matched TEXT, comments included.** It now runs on the
  source with comments stripped (string literals kept). It forbids an
  empty-object or empty-array coalesce ANYWHERE in the code, not only inside
  `NextResponse.json(...)`, and `.catch(() => ({}))`. It requires the 204 to
  be the answer to `result === undefined` and nothing else, which closes the
  reverse direction. The false "no route emits one today" is scoped to the six
  proxied routers.

## After the first review (`f4169c5`)

Two premises in this entry and in the tests were false, and are corrected:

- "Every payload this route accepts produces alphabetical types": the ZT
  answer PATCH with `{"maturity_stage": true, "notes": 5}` gives
  `schema_value_error` then `schema_string_type`, which `sorted()` reverses.
  A route-level test now asserts that literal list, and a `sorted()` at the
  handler goes red there.
- "No route produces two errors of one type": `POST /auth/register` with `{}`
  gives three `missing`. The same-type test now goes through that route
  instead of a stubbed handler call.

The proxy test also changed:

- It forbids `?? null` (in a helper anywhere, and inside a
  `NextResponse.json(...)` anywhere), `?? ({})` with a parenthesis, and a
  block-body arrow returning an empty value. It names what it does NOT model:
  `Promise.resolve({})`, a spread, `Object.assign`, an `async` arrow, and a
  value built in a variable first.
- It asserts, per file, that the comment-stripped code still has an `export`
  (and, in a helper, `NextResponse`), so an over-strip cannot pass silently.
- The 204 check is split into two assertions, each naming its own cause.
- The auth sentence is corrected: its only 204 is `/auth/logout`, which no
  proxy fronts.
