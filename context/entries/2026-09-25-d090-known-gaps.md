# 2026-09-25: the exit convention's known gaps close (#597, #592)

Branch `track1/d090-gaps`, branch-start base `2028f38`. Both are gaps that
D-090 (#591) names; D-090 itself is not edited here.

## What changed

- **#597.** `check_mount_matches_database.py` took no arguments and read none,
  so `--help` or a typo ran the check as though it were absent. It now
  refuses ANY argument with exit 2 and names it, before reading anything.
  `__main__` passes `sys.argv`, and `test_gate_crash_exit_code.GATES` says so.
  `tests/gates/argument_guards.sh` drives shell scripts only, so the guard is
  pinned by unit tests: one per argument shape, and one running the real
  command line.
- **#592.** A clean line now says what it read.
  - `check_audit_evidence.py`: the number of changed paths read, how many
    count as code, and that the body has the section, the `Findings:` line and
    the `Disposition:` line. The exempt line gives the path count too.
  - `check_issue_references.py`: the title's and description's length in
    characters, and the number of lines of commit messages (the commits file
    is every message concatenated, so it is measured in lines, not commits).

The old clean strings were grepped first as needles across tests, fixtures,
`e2e/` and the workflows. The only matches that assert are the exit codes in
`close_guard_linked_file.sh`, which are unchanged; the rest quote the old text
as history.

## Proof

Red on revert, seven mutations, each red on its named test: the argument
guard removed; `__main__` calling `main()` bare; each clean line reverted
(three lines); the audit gate counting every path as code. The new tests
assert the clean lines as literals written from the requirement, not built
from the gates' format strings.

## After the first review (`1e300af`)

- The mount gate's DEFERRED entry no longer says it reads argv nowhere or has
  four could-not-look branches: it has five, and the argument refusal is
  reachable through argv. That branch is NOT given a fixture case: this
  harness takes a gate's fixtures only with a 0, a 1 and a 2 together, and
  never alongside a DEFERRED entry, and this gate's 0 and 1 need a database.
  It is pinned by the unit tests instead, one of which runs the real command
  line. The module docstring lists the argument exit.
- The audit gate's clean line says "an `Adversarial audit` heading", because
  the heading is matched at any level and in any case; a test pins that with
  a lowercase `###` heading.
- The issue guard refuses an EMPTY commits file with exit 2: a pull request
  always has a commit, so empty means the collection failed. Two older
  tests used an empty commits file for convenience; they now use a message
  with no numbers, which keeps what each tests.
